# mc_kortex patch: source contract

The three files are the driver sources that ran the July 2026 sessions on the laboratory laptop
(`KinovaRobot.cpp`, `KinovaRobot.h`, `mc_kortex.cpp`; the rest of mc_kortex is unchanged).

- Robot B loaded from the installed `Kinova` RobotModule as instance `kinova`; Robot-B frames `base_link`, `tool_frame`.
- Robot B's physical gripper channel: disabled and not created ("plain-arm mode").
- `mc_kortex` maps Robot A `gen3_joint_1..7` and Robot B `joint_1..7` independently; per-robot map
  initialization is mandatory.
- Shutdown closes Kortex sessions, routers and transports without letting an exception escape the
  destructor (a session timeout after a successful `--init-only` preflight used to terminate the process).
- A gated joint-space override for physical Robot B: only when the driver is started with
  `CALL_PHYSICAL_ROBOT_B_FIXED_JOINTS=1`, and only after it receives `SIGUSR2`, the driver stops following
  the controller's Robot-B references and interpolates the seven real joints from their measured values to a
  fixed target on the `pure_x` time law (5.05 s), then holds. It was used in the 13:10–13:39 runs of
  18 July 2026, produced a Kinova joint fault once, and was left off from 13:53 on; the runs from then on,
  and this repository's procedure, drive Robot B with the joint references generated by the giver
  coordinator. Without the environment variable the code path is inactive.
- Robot A's receiver source is untouched by the driver.
